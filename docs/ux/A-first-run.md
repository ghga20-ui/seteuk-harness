# A · 첫 실행의 마찰

대상: 클로드 코드를 방금 결제·설치한 고등학교 교사. 학기 말, 채점은 끝났고, 세특 48명분이 남았다.
검사 대상: `C:\Users\admin\.claude\skills\seteuk-harness\` 의 `SKILL.md`, `사용안내.md`, `README.md`, `tools\도구.html`, `scripts\pseudonymize.py`.

## 0. 한 줄 요약

**이 도구는 "무엇을 하는가"는 설계돼 있는데 "지금 내가 어디에 있는가"가 설계돼 있지 않다.**
화면은 두 번뿐인데 그 두 화면 모두 앞뒤가 대화에 매달려 있고, 화면이 만들어 낸 파일이 어디로 갔는지·무엇을 다시 어디에 둬야 하는지를 **화면도 대화도 책임지지 않는다.** 첫 30분의 실패는 대부분 여기서 난다. 두 번째 축은 시간 기대치다 — 30분 뒤 교사 손에 세특은 한 문장도 없다.

## 2. 마찰 목록

심각도 — 🔴치명(오귀속·데이터 유실·이탈) / ⚠중간(막히고 물어볼 데 없음) / ▫사소
분류 — **[화]** 화면으로 / **[대]** 대화(스킬 지시문)로 / **[워]** 워크플로 자체를 바꿔야

### F1 · 스킬을 무슨 말로 부르는지 모른다 ⚠ **[대]**
> README: "설치가 끝나면 **"세특 작성해줘"** 또는 **"과세특 생성"**이라고 요청하는 순간 스킬이 동작합니다."

이 문장은 **깃허브 README에만** 있다. 설치를 마친 교사가 보는 것은 클로드 코드의 대화창이고, 거기서 "사용법을 알려줘"에 대한 답은 매번 다르다. 스킬 폴더 안 `사용안내.md`는 「진행 순서」부터 시작해서 **호출 문구가 없다.**
무엇을 몰라서 막히나: "스킬"이 자동으로 붙는 것인지, `/명령어`를 쳐야 하는지, 정확한 주문이 있는지.
→ 설치 응답의 마지막 줄을 고정한다: **「다음 줄을 그대로 붙여넣으세요 →  세특 써줘」**. `사용안내.md`의 첫 섹션도 이 한 줄로 시작해야 한다.

### F2 · 파이썬 설치가 UAC·프록시에서 끝난다 ⚠ **[대]**
학교 데스크톱은 관리자 계정이 아닌 경우가 흔하다. SKILL.md는 6항에서 "자동 설치까지 실패한 경우에만 수동 안내"라고만 한다 — 교사가 보는 건 빨간 오류 로그다.
→ winget 실패 시 **"학교 컴퓨터는 설치 권한이 막혀 있을 수 있습니다. 개인 노트북에서 하시거나 정보부에 Python 3.12 설치를 요청하세요"** 한 줄로 끊어야 한다.

### F3 · 설치 직후 파이썬을 못 찾는다 🔴 **[대]**
`winget` 설치는 성공했는데 같은 세션의 다음 명령이 또 실패한다(PATH는 프로세스 시작 시점 값). SKILL.md 2항의 "설치 후 새 셸에서 다시 탐지해 경로 반영을 확인한다"는 **에이전트에게는 참이지만 교사에게는 거짓이다** — Bash 툴의 새 셸도 같은 부모 PATH를 물려받는다.
→ 폴백을 지시문에 명시: 표준 설치 경로(`%LOCALAPPDATA%\Programs\Python\Python312\python.exe`)를 직접 시도하고, 그래도 안 되면 **"클로드 코드를 완전히 닫았다 다시 열어 주세요. 지금까지 정한 것은 없으니 처음부터 다시 말씀하시면 됩니다"** 라고 안심을 붙여 안내한다.

### F4 · 재시작 = 완전 초기화 ⚠ **[워]**
첫 실행은 재시작될 확률이 높은데(F2·F3), 재시작하면 위키 선독부터 전부 반복된다. 인터뷰 뒤에 끊기면 7문항을 다시 답해야 한다.
→ 인터뷰 확정값은 이미 `활동프로파일.json`에 쓰기로 돼 있다(SKILL.md 2단계 말미). **문항마다 즉시 기록**하고, 재시작 시 "지난번에 여기까지 정하셨습니다. 이어서 할까요?"로 복구한다.

### F5 · 파일 위치를 어떻게 주는지 모른다 ⚠ **[대]**
"학생 원본이 어디 있나요?"에 교사가 줄 수 있는 답은 파일 **이름**뿐이다. 경로 개념이 없다.
→ 작업 폴더를 먼저 확정하고(`cwd`), 그 폴더의 파일 목록을 **번호 붙여 보여 준 뒤 번호로 고르게** 한다. 경로를 타이핑하게 만들지 않는다.

### F6 · 도구.html을 여는 책임이 교사에게 있다 ⚠ **[워]**
> SKILL.md 7-1: "그 사본의 절대 경로를 사용자에게 알려 열게 한다"

경로를 알려 주는 것과 열리는 것은 다르다. 교사는 경로 문자열을 어떻게 다뤄야 하는지 모른다.
→ 복사 직후 **`start 도구.html`(Windows) / `open`(macOS)로 에이전트가 직접 연다.** 권한 프롬프트 한 번이 추가되지만, 그건 교사가 이미 익숙해진 형태의 마찰이고 경로 탐색은 그렇지 않다.

### F7 · 페이지가 "지금 어느 단계인지" 말하지 않는다 ⚠ **[화]**
탭 두 개가 나란히 있고 둘 다 눌린다. 첫 방문에서 「검수」 탭을 누르면 `파일 선택 / 선택된 파일 없음`만 있는 빈 화면이 나온다. 라벨조차 없다.
→ 검수 탭은 번들을 받기 전까지 **"세특 초안이 나온 뒤에 쓰는 화면입니다. 지금은 왼쪽 탭에서 명단부터 확정해 주세요."** 를 본문으로 보여야 한다. 파일 입력에는 `검수번들.json 불러오기` 라벨을 붙인다.

### F8 · 헤더 경로에서 출석번호를 학번으로 읽고, 경고가 없다 🔴 **[화]**
`도구.html`의 열 판별:
```js
const HEADER_ID = ["학번", "번호", "학생번호", "학년반번호"];
const headerId = head.findIndex(c => HEADER_ID.includes(c));
```
나이스 명렬(`반│번호│학번│성명`)에서 `findIndex`는 **"번호"(출석번호) 열을 먼저 잡는다.** 그런데 1~2자리 경고는
```js
if (cols.via === "값 판별" && cols.idLen && cols.idLen <= 2)
```
**"값 판별" 경로에서만** 뜬다. 헤더 경로에서는 침묵한다. 화면에는 `48명 · 중복 0 · 빈칸 0`이 초록으로 뜨고, 회색 한 줄로 `2번째 열을 학번으로 읽었습니다`만 남는다. 이 명렬이 그대로 `제출자.json`·`점수원본.json`·매핑·최종 xlsx까지 흘러가고, `verify_seteuk`의 명렬 대조는 **명렬을 명렬로 검증하는 항진명제**라 100% 통과한다(SKILL.md 저장 게이트가 스스로 인정하는 구조).
"실측에서 명렬 인식의 63%가 오류 없이 틀렸다"(PRODUCT.md)는 바로 이 계열의 실패이며, **붙여넣기 경로도 아직 이 실패를 막지 못한다.**
→ ① 헤더 경로에도 자릿수 검사를 적용한다. ② 판별 결과를 열 번호가 아니라 **첫 행 실제 값으로** 보여 준다: **「학번으로 읽은 값: 3 · 7 · 12 … / 이름으로 읽은 값: 김가온 · 이서준 …  ← 맞습니까?」** ③ 후보 열이 둘 이상이면(‘번호’와 ‘학번’이 다 있을 때) **고르게 한다.** 이건 PRODUCT.md 설계 원칙 1·2의 정확한 적용 지점이다.

### F9 · 미제출자를 아직 모르는 시점에 미제출을 묻는다 🔴 **[워]**
화면: `전원 제출` / `미제출 3명 — 활동 참여 사실만 담은 예외 세특으로 처리됩니다.`
그런데 SKILL.md 7-2는 **"원본에 답안이 있는 학번만 제출자로 한다"** — 즉 제출 여부는 답안 파일을 파싱해야 알 수 있는 파생값이다. 순서가 뒤집혀 있다. 교사는 기억으로 체크하거나(오류), 전원 제출로 두고 넘어간다(기본값이 곧 오답).
→ 두 갈래 중 하나. ㉠ 명단 확정과 제출 확정을 분리해, 답안 파싱 후 **"원본에 답안이 없는 학번 4명입니다. 미제출이 맞습니까?"** 를 대화로 확인한다(화면 체크박스는 그 결과를 보여 주는 용도로만 남긴다). ㉡ 화면에 남긴다면 기본값을 "제출"이 아니라 **"미정"** 으로 두고, 저장 시 미정이 남아 있으면 막는다. **지금처럼 전원 체크된 채로 넘어가는 것이 가장 나쁘다.**

### F10 · 점수 화면의 `누락 18`이 무엇인지 알 수 없다 ⚠ **[화]**
> `제출자 중 점수가 붙여넣기에 없는 학생 18명.`

정상일 수도(수행 미실시), 사고일 수도(반이 다른 시트에 있음) 있다. 화면은 노란 칩 하나로 끝낸다.
→ 문구를 원인 가설과 다음 동작으로 바꾼다: **「점수가 없는 학생 18명입니다. 채점표가 반별로 나뉘어 있으면 나머지 반도 이어서 붙여넣으세요. 실제로 미응시라면 그대로 두셔도 됩니다.」**

### F11 · 저장이 브라우저 다운로드 차단에 걸린다 🔴 **[화]**
`saveFile()`은 `showSaveFilePicker` → 실패 시 `<a download>` 폴백이다. **`file://`에서 열린 페이지에서는 크롬·엣지가 파일 선택기를 거부**하므로 사실상 항상 다운로드 경로이고, 파일이 2~3개라 크롬의 **"파일 여러 개 다운로드" 차단 배너**가 뜬다. 차단을 누르면 `명렬.json`만 남고 `제출자.json`·`점수원본.json`이 조용히 사라진다 — 그런데 화면의 완료 문구는 세 개를 다 저장한 것처럼 말한다:
> `저장했습니다(내려받기 폴더) — 명렬 48명, 제출자 48명, 점수 30명`

→ ① 저장을 **파일 3개가 아니라 1개**로 합친다(`세특입력.json` 하나 안에 명렬·제출자·점수 세 블록). 다운로드 차단도, 파일 이름 6종 문제(F12)도 절반이 사라진다. ② 합치지 않는다면 저장 후 **파일 목록을 화면에 남기고**, 다운로드가 실제로 몇 개 이뤄졌는지 확신할 수 없다는 사실을 문구가 반영해야 한다.

### F12 · 파일 6종을 화면이 구분해 주지 않는다 🔴 **[화]**
현재 화면에서 파일 이름이 등장하는 곳은 세 군데뿐이다.
- 저장 중 잠깐 스치는 `명렬.json 저장 중…`
- 페이지 **맨 아래** 회색 단락:
  > "**명렬.json·점수원본.json·검수본.json에는 실명이 들어 있으므로 AI에게 주지 마십시오** — AI에게 줄 것은 `검수diff.json`뿐입니다."
- 검수 탭 저장 후: `AI에게는 검수diff.json만 주세요.`

문제가 셋이다.
1. **위치.** 실명 경계는 이 도구의 존재 이유인데(설계 원칙 3), 그 설명이 두 탭 모두의 스크롤 최하단, 가장 작은 회색 글씨에 있다. 저장 버튼 옆이 아니다.
2. **불완전.** `제출자.json`은 목록에 없다. 학번이 든 파일인데 "실명 목록"에 빠져 있으니, 문장을 곧이곧대로 읽으면 **넘겨도 되는 파일**로 읽힌다. `점수원본.json`은 반대로 이름이 없는데 "실명이 들어 있다"고 적혀 있다. 둘 다 틀린 방향은 아니지만 **경계선이 임의로 보이면 교사는 경계 자체를 안 믿는다.**
3. **비대칭.** 6종 중 교사가 **직접 다뤄야 하는 것은 2종뿐**이다 — 브라우저에 넣을 `검수번들.json`, AI에게 줄 `검수diff.json`. 나머지 4종은 에이전트와 CLI만 만진다. 그런데 화면은 6종을 동등하게 나열한다.

→ 화면이 파일을 **역할로** 부른다. 저장 직후 그 자리에 고정 박스:
> **이 컴퓨터에만 두는 파일** — 명렬.json, 제출자.json, 점수원본.json  ·  세 개 모두 활동 폴더에 두세요. AI가 알아서 씁니다.
> **AI에게 주는 파일** — (아직 없음. 검수를 마치면 생깁니다.)

검수 저장 후에도 같은 박스가 뒤집힌 채로 나온다. **"주지 마십시오"보다 "이건 주는 것"이 화면에 있어야 판단이 가능하다.**

### F13 · 파일을 옮겼는지 대화가 확인하지 않는다 ⚠ **[대]**
교사는 "저장했어요"라고 말한다. 실제로는 내려받기 폴더에 있다. SKILL.md는 "내려받기 폴더에서 옮기게 안내한다"고만 돼 있다.
→ 에이전트가 **먼저 확인한다.** 작업 폴더에 없으면 내려받기 폴더를 직접 찾아 **"내려받기 폴더에 있어서 활동 폴더로 옮겼습니다"** 하고 처리한다. 파일 이동은 교사가 배워야 할 개념이 아니다.

### F14 · 30분 뒤에 세특이 0문장이라는 걸 아무도 예고하지 않는다 🔴 **[대]**
`사용안내.md`는 "한 번에 완성되지 않습니다… 대화가 길어지는 대신 선생님 문체로 나옵니다"라고 성격만 말한다. **소요 시간이 없다.** 마감 앞의 교사는 20분쯤 지나 "이거 지금 뭘 하고 있는 거지"에서 이탈한다 — 그리고 이탈처는 붙여넣고 버튼 누르면 쏟아지는 웹 서비스다(PRODUCT.md가 지목한 바로 그 반참조).
→ 스킬이 붙는 **첫 응답**에 여정 지도를 준다. **「첫 회차는 1시간 안팎입니다. 명단 확정(10분) → 규칙 7문항(10분) → 구조 고르기(10분) → 표본 3명 확인(10분) → 전체 생성(자동, 15분) → 검수(선생님 속도). 다음 회차부터는 30분입니다.」** 그리고 각 단계 진입 시 **「4단계 중 2단계」** 를 말한다. 이건 진척 표시가 아니라 **이탈 방지 장치**다.

### F15 · 바이트가 두 개 뜨고 어느 쪽이 NEIS 기준인지 화면이 말하지 않는다 🔴 **[화]**
검수 탭 헤더:
> `바이트는 UTF-8과 2바이트 기준을 함께 보여 줍니다(기준 확정 전).`

학생 카드:
> `712 바이트(UTF-8)   700 (2바이트 기준)   상한 760 초과`

세 가지 문제. ① **"기준 확정 전"은 개발자의 미결 사항이지 교사에게 할 말이 아니다.** 이 도구를 못 믿을 이유로 읽힌다. ② 초과 판정(`over`)은 **UTF-8 기준으로만** 한다 — 한글은 UTF-8에서 3바이트, NEIS·엑셀 수식(`(LENB-LEN)*2+LEN`)은 2바이트다. 즉 **화면은 NEIS와 다른 자로 재고, 다른 자로 빨간 경고를 낸다.** ③ 저장된 xlsx의 바이트 열(2바이트 수식)과 이 화면의 숫자가 다르다. 교사는 두 화면을 오가며 어느 쪽이 맞는지 판단할 근거가 없다.
→ **2바이트(NEIS) 기준 하나만 크게 보여 주고**, 초과 판정도 그 기준으로 한다. UTF-8 값이 필요하면 작게 부기하되 이름을 "참고"로 낮춘다. 첫 회차 교사에게 기준이 두 개라는 사실 자체가 마찰이다.

### F16 · 검수번들을 어떻게 얻어 어디서 여는지가 대화에만 있다 ⚠ **[대]**
`review-bundle` CLI는 에이전트가 돌리고, 그 결과를 교사가 **다시 브라우저에서 불러야** 한다. 화면 → 대화 → 화면으로 두 번 넘어가는 유일한 지점인데, 검수 탭은 "여기에 그 파일을 넣으세요"라고 말하지 않는다(F7).
→ 에이전트가 번들 생성 직후 **도구.html을 다시 열고**, 대화에는 **「방금 연 화면의 「검수」 탭에서 `검수번들.json`을 불러 주세요. 활동 폴더에 있습니다.」** 한 줄만 남긴다.

### F17 · 검수 저장에서 다운로드 차단이 다시 난다 🔴 **[화]**
`검수본.json` + `검수diff.json` 연속 저장 — F11과 동일 구조. 여기서 두 번째 파일이 차단되면 **AI에게 줄 유일한 파일이 사라진다.** 그런데 완료 문구는 저장된 것처럼 말한다: `저장함(내려받기 폴더) — 수정 12건. AI에게는 검수diff.json만 주세요.`
→ 저장 결과를 파일별로 확인해 화면에 남기고, 차단이 감지되면 **재시도 버튼**을 준다.

### F18 · 저장했는데도 창을 닫을 때 경고가 뜬다 ⚠ **[화]**
```js
const dirty = ROSTER.state.students.length > 0 || ...
```
붙여넣기만 하면 영구히 `dirty`다. 저장을 마치고 닫아도 브라우저 경고가 뜬다. 이 사용자층은 예상 못 한 시스템 대화상자에서 **자기가 뭘 잘못했다고 판단하고 멈춘다.**
→ 저장 시각 이후 변경이 없으면 경고하지 않는다.

### F19 · 명렬을 다시 불러올 방법이 없다 ⚠ **[화]**
브라우저를 닫으면 명단은 사라진다. 나중에 미제출 한 명을 고치려면 48행을 처음부터 다시 붙여넣어야 한다.
→ 탭 A에도 `명렬.json 불러오기`를 둔다(검수 탭에 이미 있는 것과 같은 입력).

### F20 · `안내` 시트·"검수 전 NEIS 금지"가 화면에 없다 ⚠ **[화]**
이 경고는 xlsx 첫 시트와 대화 보고에만 있다. 정작 **교사가 세특 문장을 실제로 보는 화면(검수 탭)** 에는 없다. 그리고 검수 탭에서 저장한 `검수본.json`은 실명·완성문 그대로라, 이걸 그대로 옮겨 쓰는 게 가장 짧은 길이다.
→ 검수 탭 최상단에 상시 한 줄: **「검수를 마치기 전에는 NEIS에 넣지 마세요. 사실과 다른 서술이 없는지 확인하는 것이 이 화면의 목적입니다.」**

## 3. CLI를 교사가 직접 치는 지점

**정당한 지점: 없다.** 파이프라인의 모든 CLI는 SKILL.md상 에이전트가 실행한다. 문제는 **문서가 교사에게 명령을 보여 준다**는 점이다.

`사용안내.md` 8절:
```
py <스킬경로>/scripts/pseudonymize.py destroy --dir <활동폴더>        ← 목록만 보여줌
py <스킬경로>/scripts/pseudonymize.py destroy --dir <활동폴더> --yes  ← 실제 삭제
```
`도구.html` 하단:
> `pseudonymize.py destroy --dir <활동폴더> --yes`로 중간 파일을 파기하세요.

교사는 `<스킬경로>`·`<활동폴더>`를 무엇으로 바꿔야 하는지 모르고, `--yes`가 붙은 쪽이 **되돌릴 수 없다**는 것만 안다. 겁이 나서 **아무것도 안 한다** → 실명이 든 중간 파일이 바탕화면에 영구히 남는다. **이 도구의 개인정보 설계가 마지막 한 걸음에서 무너지는 지점이다.**

→ 세 가지 다.
- **[대]** 회고를 마치면 에이전트가 **먼저 제안한다**: 「정리할 파일이 6개 있습니다(명렬·매핑·제출자·점수·점수원본·토큰본). 지울까요?」 → "네" 한 마디로 `--yes`까지 에이전트가 실행.
- **[화]** `도구.html` 하단 문구에서 명령줄을 **지운다**. 대신 **「검수가 끝나면 클로드에게 "중간 파일 정리해줘"라고 말씀하세요.」**
- **[대]** `사용안내.md`의 명령 블록도 같은 자연어 한 줄로 교체. 명령은 `<details>` 안에 접어 둔다.

같은 원칙이 `--column R`(사용안내 문제해결 표)에도 적용된다. 교사가 알아야 할 것은 **"어느 열인지 클로드에게 말해 주면 된다"** 이지 플래그 이름이 아니다.

## 5. 지금 고칠 다섯 개 (순서대로)

1. **F8 · 열 판별을 값으로 확인시킨다.** 헤더 경로 자릿수 검사 + 「이 값들이 학번이 맞습니까?」 확인. 이 도구가 방어한다고 선언한 실패를 지금은 방어하지 못한다.
2. **F11+F12+F17 · 파일 저장을 하나로 합치고, 저장 자리에 파일의 역할을 남긴다.** 다운로드 차단·이름 6종·"어느 걸 AI에게"가 한 번에 정리된다.
3. **F14 · 첫 응답에 여정과 소요 시간을 준다.** 이탈 방지.
4. **CLI 노출 제거(3절).** 파기가 실행되지 않으면 개인정보 설계 전체가 무의미해진다.
5. **F15 · 바이트 기준을 하나로.** 검수 화면의 숫자를 못 믿으면 검수를 안 한다.

## 부기 · 미학 쪽에서 한 가지

기능과 별개로, 현재 `도구.html`의 `h2`/`h3`가
```css
font-size:.78rem; text-transform:uppercase; letter-spacing:.08em; color:var(--muted);
```
— 한글에는 `uppercase`가 무효라 실효는 없지만, **작고 넓게 자간 준 회색 라벨**이라는 형태 자체가 금지 목록의 "모든 섹션 위 작은 대문자 eyebrow"다. 여기에 `1 ·` `2 ·` `3 ·` `4 ·` 번호가 붙어 "01/02/03 스캐폴딩"의 인상까지 겹친다. 마법사 화면이라 순서 표기 자체는 정당하나, **라벨을 본문 크기의 평범한 소제목으로 되돌리고 번호는 순서가 실제로 잠기는 곳(저장 전까지 4가 비활성)에서만** 쓰는 편이 이 도구의 성격("읽는 도구, 조용함")에 맞는다.
