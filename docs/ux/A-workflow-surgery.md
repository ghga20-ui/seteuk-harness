# A · 워크플로 수술

seteuk-harness의 교사 동작 흐름을 다시 자른다. 대상은 화면·대화·파일의 **경계**이고, 규칙은 하나다 — 각 제안은 (1) 무엇을 바꾸는가 (2) 교사 동작이 몇 개에서 몇 개로 주는가 (3) 코드 변경 범위가 어디까지인가를 반드시 적는다.

계약 확인은 실제 코드에서 했다:
`scripts/pseudonymize.py`(2364줄, CLI 7개: roster/issue/mask/memo/score/finalize/review-bundle/destroy),
`scripts/verify_seteuk.py`(438줄, `load_submitted_ids` 117–157행, `SENSITIVE_GLOBS` 1456행),
`tools/도구.html`(754줄).

## 1. 브라우저를 두 번 여는 것 — 옳다. 단, "두 번 여는 것"이 아니라 "한 페이지의 두 순간"이어야 한다

두 순간 사이에는 20~60분의 대화(인터뷰·구조·파일럿·생성·검증)가 있다. 그 시간 동안 페이지를 띄워 두면 실명 명단이 브라우저 메모리에 눌러앉는다 — 지금 코드가 `showTab()` 주석에서 "탭 사이에 자료를 저장하지 않는다(실명이 브라우저에 눌러앉지 않게)"고 명시한 그 판단은 옳다. **합치지 않는다.**

대신 지금 잘못된 것은 두 가지다.

### 1-A. 검수 탭이 처음부터 아무 설명 없이 활성화되어 있다
첫 회차 교사가 상단 "검수"를 누르면 빈 파일 선택기가 나온다. 무엇을 골라야 하는지도, 지금 할 일이 아니라는 것도 화면에 없다.

- **바꾸는 것**: 번들이 로드되기 전 검수 탭 본문에 한 줄.
  > 아직입니다. 초안 생성과 기계 검증이 끝나면 활동 폴더에 `검수번들.json`이 생깁니다. 그때 이 탭으로 돌아오세요.
- **동작 변화**: 첫 회차의 헛클릭 1회 제거(측정 불가하지만 확신 오류를 없앤다).
- **코드 범위**: `도구.html` 탭 B의 `#rv-head` 초기 문구 5줄. CLI 무관.

### 1-B. 여는 사람이 교사다
지금 SKILL은 "사본의 절대 경로를 사용자에게 알려 열게 한다". 경로를 읽고 탐색기에서 찾아 더블클릭하는 것은 이 사용자가 가장 위축되는 동작이다. 에이전트는 그 경로를 알고 있고, 열 수 있다.

- **바꾸는 것**: 복사 직후 에이전트가 `Start-Process <경로>`(Windows) / `open <경로>`(macOS)로 직접 연다. 실패했을 때만 경로를 안내한다.
- **동작 변화**: 1 → 0 (동작 #1 소멸).
- **코드 범위**: `SKILL.md` 1-7-1) 경로 A 문단 한 줄. 코드 0.

### 1-C. 다회차 학급에서는 검수 탭이 N번 열린다
SKILL은 3개 학급 이상이면 반 단위 분할 실행을 권한다. 검수번들도 반별로 생기므로 검수 탭을 반 수만큼 다시 연다. 번들에는 이미 `반` 키가 있고 카드에 태그로 뜨지만, **필터가 없다.**

- **바꾸는 것**: "우선 검토만" 옆에 반 선택(전체/1반/2반…). 여러 번들을 이어 로드하면 누적.
- **동작 변화**: 검수 탭 열기 N회 → 1회, 파일 선택 N회 → N회(그대로).
- **코드 범위**: `도구.html` REVIEW 모듈 ~20줄(`render()` 필터 조건 + 셀렉트 1개 + `load()`의 누적 병합). CLI 무관.

## 2. 손으로 파일을 옮기는 동작 — 없앨 수 있다. 에이전트가 회수하면 된다

지금 화면은 "위치를 묻지 않는 브라우저에서는 내려받기 폴더로 떨어지니 활동 폴더로 옮겨 주세요"라고 말한다. 이것은 도구가 못 하는 일을 사람에게 넘긴 문장이다. **에이전트는 두 폴더를 다 안다.**

### 2-A. 회수는 에이전트가 한다
- **바꾸는 것**: 저장 안내 직후 에이전트가 활동 폴더와 `%USERPROFILE%\Downloads`(macOS는 `~/Downloads`)를 함께 확인하고, 내려받기 쪽에 있으면 활동 폴더로 **옮긴 뒤** "내려받기 폴더에 떨어진 파일을 활동 폴더로 옮겼습니다"라고 보고한다. 파일 내용은 열지 않는다(이름과 존재만 확인 — 불변 원칙 유지).
- **동작 변화**: 동작 #9, #15 소멸 (최대 5개 이동 → 0).
- **코드 범위**: `SKILL.md`에 회수 절차 3줄. 코드 0. (`(1)` 같은 중복 접미사가 붙은 사본을 그대로 옮기지 않도록 "가장 최근 것 1개만" 규칙을 함께 적는다.)

### 2-B. 화면은 저장할 폴더를 말로 알려 준다
페이지는 활동 폴더에 복사된 사본이므로 `location.href`로 자기 위치를 안다.

- **바꾸는 것**: 저장 카드 문구를 실제 경로로. 마이크로카피 —
  > 저장 위치를 물으면 이 폴더를 고르세요 — `C:\...\2학년 문학\소설 비평하기`
  > 위치를 묻지 않는 브라우저면 내려받기 폴더에 떨어집니다. 그건 그대로 두셔도 됩니다 — 제가 가져오겠습니다.
- **동작 변화**: 저장 대화상자에서 폴더를 헤매는 시간 제거(동작 수는 동일).
- **코드 범위**: `도구.html` `#savecard` 안내문 + `decodeURIComponent(location.href)`에서 폴더 추출 6줄.

## 3. JSON 6종 → 3종. 단, **합쳐도 되는 쪽과 절대 합치면 안 되는 쪽의 이유가 다르다**

교사가 손으로 만지는 JSON은 6개다. 나가는 것 3개(`명렬.json`·`제출자.json`·`점수원본.json`), 들어오는 것 1개(`검수번들.json`), 다시 나가는 것 2개(`검수본.json`·`검수diff.json`).

### 3-A. 나가는 3개 → 1개. **파일 이름을 `명렬.json` 그대로 두면 CLI 변경이 거의 없다** (권장)

`도구.html`의 저장 버튼이 다음 한 파일만 쓴다.

```json
{ "students": [{"학번":"30101","이름":"김가상"}, ...],
  "학번목록": ["30101", ...],
  "항목":     [{"학번":"30101","점수":15}, ...],
  "인원":     48,
  "출처": "도구.html (붙여넣기)", "방식": "붙여넣기",
  "제출확정": "교사 체크(도구.html)",
  "확인필요": false, "확인사유": [], "중복": 0 }
```

계약을 읽어 확인한 대가는 다음과 같다.

| 호출부 | 지금 | 합친 뒤 | 코드 변경 |
|---|---|---|---|
| `issue/mask/memo/score/finalize --roster` | `roster["students"]` | 그대로 동작 | **0** — 추가 키는 무시된다(이미 `출처`·`확인필요` 등이 들어 있다) |
| `verify_seteuk --roster` | `roster.get("students")` (184행) | 그대로 동작 | **0** |
| `score --paste` | `obj.get("항목")` (1393행) | 그대로 동작 | **0** |
| `destroy` / 잔존 감지 | `SENSITIVE_GLOBS`에 `명렬*.json` 포함 (1456행) | 그대로 잡힌다 | **0** (`제출자*.json` 항목은 남겨 둔다 — 구 회차 호환) |
| `verify_seteuk --submitted` | `load_submitted_ids`가 `학번목록` **∪** `students` **∪** `map` **∪** `classes`를 전부 합집합 (148–156행) | **조용히 망가진다** | **여기만 고친다** |

**유일한 진짜 대가가 이것이다.** 지금 `load_submitted_ids`는 발견되는 모든 형태를 합집합으로 모은다. 한 파일에 명렬 48명과 제출자 45명이 함께 들어가면 결과는 48명이 되고, "제출하지 않은 학생에게 세특이 생성됨" FAIL이 **영원히 발동하지 않는다.** 경고도 없다. 지금 이 도구가 가장 두려워하는 종류의 실패(조용한 통과)다.

- **고치는 방법**: `load_submitted_ids`에서 `학번목록`이 있으면 그것만 쓰고 즉시 반환(우선순위 방식). 4줄.
- **함께 바꿀 것**: 같은 함수 docstring의 "명렬과 무관한 별도 경로 데이터를 전제로 한다"는 설명이 파일 단위 논증이므로 다시 써야 한다. 독립성은 **파일이 달라서**가 아니라 **체크박스라는 별개의 교사 행위에서 나온다**로 바꾸고, `verify_seteuk` stdout에 한 줄을 반드시 남긴다:
  > 제출 대조: 명렬과 같은 파일의 체크 결과로 했습니다. 붙여넣은 명단 자체가 통째로 틀렸다면 이 대조는 통과합니다.
- **테스트**: `scripts/tests/test_attribution_gate.py`의 "제출 원본 로더가 리스트/학번목록/맵/students/classes 형태를 모두 지원한다"(182행)가 합집합을 전제하므로 우선순위 방식으로 고쳐 쓴다 + 합본 파일 케이스 1개 추가. `test_score_paste.py`는 무변경.
- **동작 변화**: 저장 대화상자 3 → 1. 손으로 옮길 파일 3 → 1(그리고 2-A로 0).
- **코드 범위**: `도구.html` 저장 핸들러 ~15줄, `verify_seteuk.py` 4줄 + docstring, 테스트 1파일.

> 대안(파일명을 `명단.json` 등으로 새로 지음)은 `SENSITIVE_GLOBS` 한 줄과 SKILL.md의 파일명 언급 전부를 함께 고쳐야 한다. **이득이 없다. `명렬.json` 이름을 유지한다.**

### 3-B. 들어오는 `검수번들.json` — 그대로 둔다
CLI가 만들고 CLI만 읽는 중간물이 아니라 화면 전용 입력이며, 이미 하나다. 줄일 것이 없다.

### 3-C. 나가는 `검수본.json` + `검수diff.json` — **합치면 안 된다. 이건 정리 대상이 아니라 안전장치다**

"한 파일로 묶고 AI에게 줄 부분만 표시하기"는 매력적으로 들리지만, 그렇게 하는 순간 에이전트는 **실명이 든 파일을 열고 스스로 눈을 가려야 한다.** SKILL의 불변 원칙("명렬 파일·매핑표·채점표를 에이전트가 직접 열어보지 않는다")을 기계적 보장에서 자율 규제로 강등시키는 변경이다. 파일 두 개는 잡음이 아니라 **집행 수단**이다.

대신 헷갈림만 줄인다.

- **바꾸는 것**: 파일명을 `검수본(실명).json` / `검수diff(AI용).json`으로. 저장 순서를 뒤집어 **`검수diff(AI용).json`을 먼저** 저장한다(첫 대화상자에서 취소해도 AI에게 줄 것은 이미 나와 있다). 저장 완료 문구:
  > 저장했습니다 — 수정 12건. **에이전트에게 줄 파일은 `검수diff(AI용).json` 하나입니다.** `검수본(실명).json`은 선생님 컴퓨터에만 두세요.
- **동작 변화**: 파일 2개 유지, 잘못된 파일을 건네는 사고 경로 제거.
- **코드 범위**: `도구.html` 저장 핸들러 파일명·순서 4줄. `SENSITIVE_GLOBS`에 `검수본*.json` 패턴이 이미 없으므로(`검수번들*.json`만 있다) **`검수본*.json` 1줄 추가** — 지금 실명 파일 하나가 파기 대상에서 빠져 있다.

### 3-D. 관찰 메모 — 텍스트 파일을 손으로 만들게 하는 동작을 없앤다 (코드 0)
지금 교사는 메모장을 열어 `학번: 메모` 형식 파일을 직접 만든다. 이 흐름에서 가장 개발자스러운 요구다. 그런데 `memo` 명령은 이미 그 텍스트 형식을 받는다.

- **바꾸는 것**: 도구.html에 "메모 (선택)" 붙여넣기 상자 하나. 학번·메모 두 열을 붙이면 `관찰메모.txt`를 `학번: 메모` 한 줄씩으로 저장한다. `python pseudonymize.py memo 관찰메모.txt ...` 는 **오늘 코드 그대로 동작한다.**
- **동작 변화**: 메모장 열기 → 형식 맞춰 타이핑 → 저장(3동작) → 붙여넣기 1회.
- **코드 범위**: `도구.html` 상자 1개 + `saveFile()`의 텍스트 변형 5줄. `SENSITIVE_GLOBS`의 `관찰메모*.json` → `관찰메모*.*` **1줄**(안 고치면 실명 메모가 파기에서 누락된다 — 지금 계획대로면 새로 생기는 구멍이다). 파이썬 파서 변경 **0**.

**결과: 교사가 만지는 파일 6 → 4(명렬·검수번들·검수diff·검수본), 저장 대화상자 5 → 3, 손으로 옮기는 파일 5 → 0.**

## 4. 대화와 화면의 경계 — 잘못 배치된 것 하나, 잘 배치된 것 둘

### 4-A. **잘못 배치됨: `--expected-count`(대상 인원)를 대화에서 묻는다. 이 게이트는 지금 이미 무력화되어 있다**

가장 중요한 발견이다.

SKILL 7절과 verify_seteuk 176–177행의 논증은 정확하다 — 명렬로 명렬을 검증하면 항진명제이므로, 산출물에서 파생되지 않은 외부 수 하나가 반드시 필요하다. 그런데 **교사는 붙여넣은 그 순간 화면에서 "48명"을 이미 보았다.** 30분 뒤 대화에서 "이 활동 대상이 몇 명입니까?"를 물으면 교사는 화면에서 본 48을 답한다. 산출물을 본 뒤에 인원을 맞춰 넣지 말라는 SKILL의 경고를, **도구의 화면이 스스로 위반하게 만들고 있다.**

- **바꾸는 것**: 인원 입력을 **붙여넣기보다 위로, 붙여넣기 전에** 옮긴다. 값을 넣기 전에는 붙여넣기 상자를 비활성화한다.
  > **이 활동 대상은 몇 명입니까?** 명단을 보기 전에 적어 주세요 — 정원에서 전출·자퇴를 뺀, 선생님이 아시는 수. 이 수는 아래에서 읽은 명단이 맞는지 대조하는 데만 씁니다.

  붙여넣은 뒤 즉시 화면이 대조한다:
  > 적어 두신 **48명**과 붙여넣은 **47명**이 다릅니다. 명단을 다시 확인하시겠습니까?

  값은 `명렬.json`의 `인원` 키로 저장되고, 에이전트는 저장 게이트에서 `--expected-count`를 **묻지 않고** 그 값을 넘긴다.
- **동작 변화**: 대화 왕복 1회 소멸(동작 #11). 그리고 무력했던 게이트가 실제로 작동하기 시작한다 — 이게 본체다.
- **코드 범위**: `도구.html` 입력 1개 + 대조 문구 ~20줄. `verify_seteuk`는 `--expected-count`를 이미 int로 받으므로 **0**. `SKILL.md` 7절에서 "교사에게 인원을 묻는다"를 "명렬.json의 `인원`을 넘긴다(없으면 묻는다)"로 수정. `활동프로파일.json`의 `인원` 재사용 로직은 그대로.

### 4-B. 잘못 배치됨(작은 것): 점수 열 모호성 질문
`score` 경로 B는 후보가 2개 이상이면 exit 1로 멈추고 "J열 — 소설 비평하기 > 점수" 같은 목록을 **대화로** 보여 준다. 열을 고르는 것은 판단이 아니라 **보기**다. 게다가 SKILL 스스로 "실측 37개 중 20개(54.1%)는 후보가 1개인데 그 1개가 틀렸다 — 어떤 파싱으로도 못 잡는다"고 적어 두었다.

- **바꾸는 것**: 경로 B를 기본 안내에서 내리고, 교사에게는 붙여넣기만 제시한다. CLI는 헤드리스·회귀 대비로 그대로 둔다.
- **동작 변화**: 최악의 경우(후보 다수) 대화 왕복 2회 + CLI 재실행 1회 → 0.
- **코드 범위**: `SKILL.md` 1-7-5) 서술 순서. 파이썬 0.

### 4-C. 잘 배치됨(옮기지 않는다): 구조 심층 인터뷰·파일럿 배치
"완성 세특 2~3개를 나란히 시연"은 눈으로 보는 일이므로 화면이 낫다고 판단하기 쉽다. **옮기지 않는다.** 옮기려면 생성된 텍스트를 파일로 내보내고 선택 결과를 다시 파일로 받아야 하며, 파일 2개와 브라우저 왕복 1회가 새로 생긴다 — 3장에서 줄인 것을 그대로 반납한다. 여기서 필요한 건 화면이 아니라 **대화의 제시 형식**이다.

- **바꾸는 것**: SKILL에 시연 출력 형식을 고정한다 — 같은 학생 1명, 후보별 완성문 전문, 차이가 나는 문장에만 표시, 끝에 한 줄 요약("A는 강점을 앞세우고, B는 성찰을 앞세웁니다"). 지금은 형식이 자유라 회차마다 비교 품질이 흔들린다.
- **코드 범위**: `SKILL.md` 3절. 코드 0.

### 4-D. 잘 배치됨: 미제출 체크(화면), 회고 패턴 승인(대화), 파기 승인(대화)
전부 원칙 4와 일치한다. 손대지 않는다.

## 5. 첫 실행에만 필요한 안내 — 어디에 둘 것인가

원칙 5는 "이 사람은 매뉴얼을 읽지 않는다"이다. 그러면 배치 규칙은 하나로 정해진다.

> **화면에는 "여기서 틀리면 되돌릴 수 없고, 어떤 검사로도 안 잡히는 것"만 둔다. 나머지는 대화가 그때그때 말하고, 문서는 사후 참조용으로 남긴다.**

이 기준을 통과하는 것은 셋뿐이다.

1. **두 열을 함께 긁기** — 따로 붙이면 행이 어긋나고, `사용안내.md`가 인정하듯 **어떤 검사로도 잡히지 않는다.** 지금은 제목 아래 회색 부제로 있어 빈 상자 위를 스쳐 지나간다. 빈 상자 자체가 안내가 되어야 한다.
   > (placeholder) 여기에 붙여넣으세요 — 엑셀에서 학번 열과 이름 열을 **함께** 드래그해서 복사하세요. 따로 두 번 붙이면 행이 어긋나고, 그렇게 어긋난 명단은 이 도구도 NEIS도 잡아내지 못합니다.
2. **대상 인원을 명단 보기 전에 적기** — 4-A. 순서가 곧 안내다.
3. **AI에게 줄 파일은 diff 하나** — 3-C의 저장 완료 문구.

나머지(설치, 준비물, 7문항 예고, 한계 목록, 문제 해결 표)는 **대화와 문서**에 남긴다. 대화는 이미 매 단계 다음 할 일을 말하고 있고, 문서는 사고가 난 뒤 찾아 읽는 물건이다.

**"처음이신가요?" 배너나 단계 투어는 넣지 않는다.** 제품 슬롭이며, 두 번째 회차부터는 순수한 소음이다. 첫 실행 감지도 하지 않는다(로컬 스토리지를 쓰면 이 페이지가 "아무것도 기억하지 않는다"는 약속이 깨진다).

### 5-A. 덤: 지금 화면이 스스로 어기고 있는 금지 사항 (이번 회차 범위 밖, 다음 회차 입력)
`도구.html`의 카드 제목은 `1 · 붙여넣기` / `2 · 확인` / `3 · 점수 (선택)` / `4 · 저장`이고, `h2`는 `text-transform: uppercase; letter-spacing: .08em; color: var(--muted)`이다. 이것은 지목된 금지 목록의 **"01/02/03 번호 스캐폴딩"과 "모든 섹션 위 작은 대문자 eyebrow"에 정확히 해당한다.** 순서는 카드가 하나씩 나타나는 것(`hidden` 해제)으로 이미 표현되고 있으므로 번호는 중복이다. 번호를 지우고 제목을 본문 조판 안으로 내리는 것이 다음 회차 과제다.
