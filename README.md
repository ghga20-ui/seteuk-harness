# seteuk-harness

수행평가 결과로 교과 세부능력 및 특기사항(과세특) 초안을 만드는 Claude Code 스킬입니다.
쓰면 쓸수록 여러분의 문체와 기준에 맞춰집니다.

## 왜 이 도구는 '딸깍'이 아닌가

붙여넣고 버튼을 누르면 세특이 쏟아지는 서비스는 이미 많습니다. 이 도구는 그 반대편에서 출발했습니다 —
**클릭 한 번으로 AI에게 세특을 받아 쓰는 것은 평가자로서의 교사 전문성을 스스로 격하시키는 일**이라는
문제의식입니다. 평가는 교사가 하고, AI는 이미 내려진 평가를 기록으로 옮기는 일을 돕습니다.
이 경계는 다짐이 아니라 동작으로 강제됩니다.

- **채점 없이는 시작하지 않습니다.** 채점표가 확인되지 않으면 생성을 거부합니다.
  세특의 수준(톤)은 교사의 점수에서 파생되고, AI의 조정 의견은 생성 전에 물어 승인된 것만 반영됩니다.
- **지어낸 문장이 스스로 자수합니다.** 검수 화면에서 세특의 문장마다 학생 원문의 근거 구절이
  ①② 번호로 짝지어지고, 근거를 찾지 못한 문장에는 `근거 못 찾음`이 붙습니다.
  "실제 있었던 일이면 두시고, 아니면 고쳐 주세요" — 판단은 교사의 몫으로 남깁니다.
- **조용히 틀리지 않습니다.** 인원이 안 맞으면 멈추고, 점수 열이 애매하면 묻고,
  미제출자에게 정상 세특이 붙으면 저장을 거부합니다. 개발 과정에서 명렬 자동 인식을
  실제 학교 파일 341개로 실측했더니 **인식 결과의 63%가 오류 없이 틀렸습니다** —
  그래서 이 도구는 확신이 없으면 진행하는 대신 멈춰서 묻도록 만들어졌습니다.
- **쓸수록 여러분의 것이 됩니다.** 검수에서 고친 것이 다음 회차의 규칙이 됩니다.
  그 축적은 여러분 컴퓨터의 `wiki/성장/` 폴더에만 쌓이고, 어디로도 전송되지 않습니다.

사람이 결정하는 지점은 채점, 규칙·구조 인터뷰, 표본(파일럿) 승인, 검수, 회고입니다.
반복 작업만 기계가 맡습니다. 학생별로 승인 버튼을 누르게 하는 식으로 사람을
"도장 찍는 기계"로 만드는 설계는 의도적으로 배제했습니다.

## 어떻게 진행되나

준비물은 활동 폴더에 넣은 **채점표와 학생 답안**뿐입니다. 화면을 조작할 일은 거의 없고,
대부분 대화입니다.

```
교사   폴더에 채점표랑 답안 넣었어. 세특 쓰자.
도구   채점표 후보가 2개 있습니다. ① …채점표.xlsx(어제 수정) ② 백업.xlsx — 어느 파일인가요?
교사   1번
도구   시트 2개를 합쳐 48명을 읽었습니다. 첫 행: 학번 30101 · 김○○ — 맞나요?
       (명단 전체는 확인.html 한 장으로 만들어 드립니다. 훑어보기만 하세요.)
```

그 뒤 규칙 인터뷰(활동명·분량·예외 처리 등 7문항), **구조 고르기**(설명이 아니라
그 학생 답안으로 쓴 완성 세특 2~3개를 나란히 보고 선택), 표본 3~4명 승인, 전체 생성,
이중 검증을 거쳐 **검수.html** 한 장이 폴더에 생깁니다. 더블클릭하면 원문과 초안이
나란히 떠 있고, 고친 뒤 저장하고 대화창에 「검수 끝났어」라고만 말하면
도구가 폴더에서 고침 기록(이름 없음)을 읽어 회고까지 진행합니다.

두 번째 활동부터는 파일·점수 열·규칙을 기억하고 있어 질문이 확 줄어듭니다.

## 손글씨 답안은 이렇게 처리됩니다 (실전 예)

종이 답안지를 폰으로 찍어 쓰는 경우입니다. 촬영 팁 하나 — **출석부 순서대로, 한 학생씩** 찍으세요.
그 순서가 학번 배정의 근거가 됩니다.

```
교사   소설 비평 답안지 48장 찍어서 폴더에 넣었어. 세특 쓰자.

도구   손글씨 답안이네요. 시작 전에 한 가지만 — 손글씨 경로는 타이핑 답안보다
       개인정보 보증이 한 단계 낮습니다. 인적사항 칸은 가리고 전사하지만,
       가림이 제대로 됐는지 기계가 검증하는 장치가 아직 없어서 전송 전에
       선생님 눈으로 확인하는 단계가 들어갑니다. 진행할까요?

교사   응

도구   첫 장을 기준으로 묻겠습니다. 이름·반·번호 칸이 답안지 어디에 있나요?
       (예: 위쪽 띠 부분)

교사   위쪽에 있어

도구   [로컬 실행 — 48장 전체의 위쪽 영역을 가린 사본 생성. 원본은 그대로 보존]
       마스킹 사본 48장을 만들었습니다. 폴더에서 서너 장만 열어
       이름이 정말 안 보이는지 확인해 주세요.

교사   확인했어, 안 보여

도구   이제 마스킹 사본만 제가 읽어 전사합니다.
       … 전사 완료: 46장 정상, 2장은 일부 [판독불가] — 지어내지 않고 그대로
       표시했고, 이 두 학생은 검수에서 '먼저 볼' 목록 맨 위에 올렸습니다.
       장수 검산: 48장 = 48명 × 1장, 사진 순서 × 명렬 순서로 학번을 배정했습니다.
       검수 때 인적사항 부분의 잘라낸 이미지와 배정 결과를 나란히 보여 드릴 테니
       순서가 밀리지 않았는지 몇 명만 표본으로 대조해 주세요.
       이후는 타이핑 답안과 똑같이 진행됩니다.
```

**손글씨 경로의 정직한 한계** — ① 학생이 본문 안에 직접 쓴 이름은 가림 영역 밖이라
전사 순간 한 번은 AI가 봅니다(산출물에서는 치환됩니다). ② 가림이 실제로 적용됐는지
확인하는 기계 검사가 아직 없어 위의 육안 확인이 필수 절차입니다. ③ 전사는 판독
신뢰도를 함께 기록하며, 낮은 학생은 검수 우선순위로 올라갑니다.

## 지원하는 답안 형식

| 형식 | 처리 | 비고 |
|---|---|---|
| xlsx(종합·구글폼 응답 CSV 포함) | 자동 추출 | 가장 매끄러운 경로 |
| hwpx, 텍스트, 확장자 위장 HTML | 자동 추출 | |
| 학생별 개별 파일 | 파일명↔명렬 대조 | 동명이인은 확인 후 진행 |
| 사진(jpg·png), 스캔 PDF | 마스킹 → 전사 | 위의 손글씨 절차, 보증 한 단계 낮음 |
| hwp(구형)·docx | 재저장 안내 | 한글/워드에서 hwpx·xlsx로 한 번만 다시 저장 |

학번은 4~6자리 모두 지원합니다. 채점은 점수제·등급제(P/F)·감점제·문항별 합산 모두 됩니다.
과목별로 금지 표현이 다르면(수학의 부등호 등) 활동 단위로 규칙을 조정할 수 있습니다.

## 개인정보 처리

학생의 실명과 학번은 AI에 전송되지 않습니다.

- 명렬 인식·토큰 치환·재결합은 전부 여러분 컴퓨터의 파이썬이 수행하고, AI는
  요약("명렬 인식: 48명")만 받습니다. AI가 세특을 쓸 때 보는 것은 `S-3F7A` 같은
  토큰과 글 내용뿐입니다.
- 학번이 하나라도 남으면 전송 자체가 차단됩니다(이중 게이트). 이메일 주소도 가립니다.
- 관찰 메모는 파일로만 받습니다 — 대화창에 적으면 그 순간 전송되기 때문입니다.
  실수로 명단을 붙여넣는 것을 막는 차단 훅도 동봉되어 있습니다(설치 선택).
- 토큰과 학생을 잇는 매핑표는 로컬 전용이며 활동이 끝나면 파기 명령으로 지웁니다.
- 검수도 로컬 문서(검수.html)에서 하고, AI에게 돌아가는 것은 이름 없는 고침 기록뿐입니다.

**그래도 남는 한계**: 글 내용 자체는 전송되므로 내용만으로 짐작 가능한 서술은 남습니다
(민감 내용 발견 시 경고). 로마자 표기 이름은 탐지하지 못합니다. AI 제공사의 로그는
이 스킬의 통제 밖입니다. 학교의 개인정보 처리 기준을 함께 확인하시길 권합니다.

## 설치

Claude Code를 열고 아래 한 줄을 붙여넣으세요. 설치는 Claude가 대신 합니다.

```
https://github.com/ghga20-ui/seteuk-harness 스킬을 내 스킬 폴더(~/.claude/skills/seteuk-harness)에
설치해줘. 끝나면 사용법을 알려줘.
```

파이썬 등 필요한 프로그램은 첫 실행 때 스킬이 스스로 확인하고 설치합니다.
이후 "세특 작성해줘"라고 말하는 순간 동작합니다.

**업데이트는 신경 쓰지 않으셔도 됩니다** — 스킬이 실행될 때마다 새 버전이 있는지
확인하고 "받을까요?"라고 묻습니다. 여러분의 성장 기록(`wiki/성장/`)은 업데이트로
덮이지 않는 위치에 있습니다.

> Codex 등 다른 코딩 에이전트: 자동 트리거는 Claude Code 전용이지만 내용물이 전부
> 마크다운과 파이썬이라 "이 폴더의 SKILL.md를 읽고 절차를 따라줘"로 사용할 수 있습니다.

## 반드시 지켜야 할 것

- **초안을 그대로 NEIS에 입력하지 마세요.** 2026 기재요령상 AI 생성문을 그대로 입력할 수
  없으며, 실제 수행과의 일치·기재요령 준수의 최종 확인 책임은 교사에게 있습니다.
  이 도구의 검수 단계는 그 확인을 돕도록 설계되어 있습니다(우선 검토 대상, 근거 짝).
- 스킬 폴더를 다른 교사에게 통째로 복사해 주지 마세요 — `wiki/성장/`에 여러분의
  검수 습관이 담깁니다. 대신 위의 설치 한 줄을 알려 주세요(GitHub 원본은 씨앗 상태라
  개인 기록이 구조적으로 담기지 않습니다).

## 문제 해결

- 파이썬·openpyxl 자동 설치가 실패하면: python.org에서 Python 3.10+ 설치 후
  `python -m pip install openpyxl`
- 학교 프록시로 설치가 막히면 관리자 문의 또는 개인 네트워크에서 설치
- 학급이 3개 이상이면 반 단위로 나눠 요청하세요(권장)
- 명렬을 읽지 못하면 화면에 원인과 해결(구형 .xls 재저장 등)이 함께 표시됩니다
